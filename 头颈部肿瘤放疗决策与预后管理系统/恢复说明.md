# 源码恢复说明

本目录已同步参考网站 `http://118.25.191.200:8080/` 当前可公开读取的前端页面、脚本、样式和品牌/影像组学图标资源。现有 `server.js` 保留，并补充了线上前端需要的接口兼容层。

## 本地启动

```powershell
powershell -ExecutionPolicy Bypass -File .\start-local.ps1
```

默认医生账号为 `doctor001 / 123456`，病人账号为 `patient001 / 123456`，与当前原站的账号一致。部署时可用环境变量 `MED_DOCTOR_PASSWORD` 和 `MED_PATIENT_PASSWORD` 覆盖默认密码。

## 已恢复的接口

- `/api/radiomics-prognosis`：读取同目录下可选的 `radiomics-results.json`；没有结果文件时返回空病例队列。
- `/doctor-tool-proxy/targetContouring/*`
- `/doctor-tool-proxy/dosePrediction/*`

两个医生工具代理会转发到 8011 和 8021 端口，并要求医生会话。已根据公开接口重建两个可启动的 Python 服务以及原站可公开访问的页面和样式。当前源码包仍缺少模型权重和推理数据，所以真实推理请求会明确返回 `503 MODEL_UNAVAILABLE`。

本地启动主服务时会尝试启动两个 Python 服务，并仅让它们监听 `127.0.0.1`。主站通过带医生登录验证的代理调用它们。两个服务的 `openapi.reference.json` 是从原站公开接口保存的参考合同；`app.py` 为重建实现，并不是原站源码。当前病例数、模型数为零，旧预测结果也不能从这些接口还原。

原站公开接口提供了一份历史靶区勾画结果。本地工作目录保存了其叠加图、分割结果和概率图；公开仓库不包含这份临床影像。它是已生成的结果，并非本地重新推理；本地仍不能对新病例生成结果。

首次启动前安装 Python 依赖：

```powershell
python -m pip install -r ..\brain_gtv_system\requirements.txt
python -m pip install -r ..\dose_prediction_system\requirements.txt
```

如果主站部署在 Linux，可在应用目录运行 `MED_HOST=0.0.0.0 MED_PORT=8080 node server.js`。确保 Python 解释器中已安装上述依赖，主服务会自动启动两个子服务。若 Python 命令不是 `python`，设置 `PYTHON` 环境变量为实际解释器路径。

## 恢复备份

替换前的完整目录保存在项目根目录下名称带 `头颈部肿瘤放疗决策与预后管理系统-backup-` 的备份目录中。

线上服务器中不可公开读取的业务数据、上传文件、AI 密钥、Python 服务源码和模型权重无法从网页前端反推出；获得这些文件后可以按代理接口直接接入。
